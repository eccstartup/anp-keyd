# 它是什么

anp-keyd 是面向 ANP Agent 的本地身份签名与有限授权服务。Agent 请求签名，长期私钥和管理权限留在托管服务中。

在 Linux 受保护部署下，daemon、管理员和 Agent 使用不同 UID。每次签名检查主体、指定热密钥、目标策略、期限、次数和撤销状态。Agent 被注入后仍可能滥用已经获准的操作，因此授权范围要足够窄，对端也要验证请求和重放状态。

| 场景 | 当前边界 |
|---|---|
| 独立 UID 的 Linux 受保护部署 | 在 OS、管理员及 daemon 可信时，限制读密钥、改策略和跨主体签名 |
| 同 UID 开发模式 | 常规 API 不返回私钥；不抵御同 UID 任意代码执行 |
| root、内核或可信管理端被控制 | 不在当前保护承诺内 |

## 管理和使用分开

管理员负责身份迁入、角色确认、可信解锁、策略、grant、撤销与轮换。Agent 只通过数据面列出获准的钥匙、读公开文档、请求结构化 HTTP 签名和查询请求状态。

密钥已解锁不代表 Agent 有权使用；grant 有效也不会自动解锁。密码不经过 MCP，普通 Agent 不能请求根密钥、raw 或 challenge 签名。TTY 只能减少口令误传，不证明人类在场。

## 身份与请求

客户端负责业务协议和网络发送；签名核心离线重建签名基并执行策略。返回签名后，客户端按规范化 URL、原始 body 和生成头发送，不自动跟随重定向。

文档生成与网络发布分别处理。注册、热密钥轮换和恢复须由可信管理流程完成，不能让 Agent 以任意文档或字节串请求根签名。

## 适合的使用方式

自有 Linux 主机上运行多个独立 UID 的 Agent，分别授予指定身份、目标、期限和次数。它们可以共享一个服务而不共享管理权限；同 UID 的不受限 Agent 仍视为同一个主体。

软件完整目录加正确口令可以解封。硬件根增加解封材料保护，但当前签名仍在软件内存中执行；备份恢复、历史密钥泄露和远端撤销各有独立边界。
