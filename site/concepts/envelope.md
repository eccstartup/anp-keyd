# 信封与归档

**这一对区分是理解整个设计的钥匙。**

| | 信封 `keys/<thumbprint>.json` | 归档 `<thumbprint>.anpkeyd.json` |
|---|---|---|
| 是什么 | 钥匙在**这台机器**上的存放形式 | 把身份**搬到另一台机器**的产物 |
| 熵从哪来 | 口令 **+** `device.secret`(+ 绑了硬件的话,第三路) | **只有**导出时的那个一次性口令 |
| 能搬机器吗 | 软件整套目录加口令可恢复；硬件依赖另验 | 能，独立口令保护的可移植副本 |
| 口令可以复用吗 | 可以,是日常口令 | **不行**,一次性,强制独立 |
| 谁生成 | `keygen` / `import-*` | `export-seed`(默认构建里不存在) |

## 信封为什么搬不走

一半的熵是这台机器的 `device.secret`。所以把 `keys/` 整个拷到另一台机器上,那边的 `device.secret` 不一样,信封就打不开。

反过来说:便携归档不依赖原 device.secret；完整软件快照则会把 device.secret 一起复制，两者都必须保护。

::: info 这是设计,不是缺陷
整份软件 `~/.anp-keyd/` 加口令可以解封；缺少 device.secret 或所需硬件根时拒绝。要在别的机器上用同一把身份,走归档那条路。
:::

熵是怎么合成的:

```
KEK = HKDF-SHA256( argon2id(口令) ‖ device.secret, salt )
```

少任何一半都开不了,而且**两者失败时的报错一模一样** —— 两者可区分等于告诉拿到磁盘的人"你缺的是哪个因子"。

## 绑了硬件根就是把这一条推到极致

`device.secret` 和信封住在同一个目录里,**所以"拷走目录"这动作会把两者一起带走**。它挡的是"备份被拷走、目录没被拷走"这种情形,而挡不住整个目录搬走。

硬件根补的正是那一路:第三份熵**根本不在文件系统上**,只在芯片里。

```
HS  = 32 随机字节,由硬件封装后存进信封(hs_ciphertext)
KEK = HKDF-SHA256( argon2id(口令) ‖ device.secret ‖ HS, salt )
```

三路少任何一路都开不了。细节和代价见[硬件根](/advanced/hardware-root)。

## 归档有个必须说清的性质

**归档文件本身就是一份可以被离线暴力破解的口令保护文件。** 它的强度等于那个口令的强度乘以 Argon2id 的成本参数,再没有别的了。

所以:

- 导出时强制要一个不弱的口令
- 导出**不重试** —— 一遍就够,不留循环
- 口令必须和日常口令**不同**,而且守护进程在导出前强制先 LOCK

## 导入之后必须说两句话

1. **这是一把克隆,不是副本。** 导入出来的钥匙和旧机器上的是**同一把**,两边都能签,而且验证方分不出来。旧机器上的那一份要处理掉。
2. **重新封装用的是这台机器的新 `device.secret` 和新口令。** 归档里的那个导出密码从此没用了。

## 两份冻结的格式

助记词推导方案(`bip39-entropy-v1`)和归档格式(`anp-keyd-archive` v1)**一旦发布就不能改**。改了的后果不是报错,是**旧的备份打不开** —— 放在用户手里的那张纸、那个文件,是他仅有的一份。
