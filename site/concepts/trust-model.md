# 信任边界

Linux v2 使用独立服务 UID、管理员 UID 与 Agent UID；可信配置由 root 持有。客户端在发送管理口令前验证路径权限和 daemon 的内核 UID。主体、exact-key grant、目标策略、次数、绝对期限、撤销与持久请求去重均在 daemon 执行。

`protected_supported=false`：真实 systemd 主机验收未完成，容器测试不等于发行验收。macOS 保留开发模式；同 UID 任意代码可以读取文件或影响进程，不能仅凭 socket 不返回私钥就声称密钥隔离。

软件整套目录和口令可以解封。硬件根保护解封材料，签名仍在普通内存中执行。SQLite 事务审计与本地哈希链不抵御管理员整体回滚。历史私钥导出不能被软件收回。

管理端批准有限范围后 Agent 可自动请求；解锁不产生授权。root/recovery 不进入 Agent grant；注册 proof 和热密钥轮换使用精确批准的管理操作。跨文件恢复只重放已批准且有审计证据的操作，遇到未知文件状态停止服务。

nonce 重放与业务幂等由验证方负责。撤销本地 grant 不撤回已交付签名；轮换文档必须发布到对端并验证生效。
