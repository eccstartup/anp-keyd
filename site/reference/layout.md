# 磁盘布局

根目录默认 `~/.anp-keyd`(`--root` 可覆盖;`--system` 下是 `/var/lib/anp-keyd/users/<uid>`)。

```
~/.anp-keyd/
├── device.secret              0600  这台机器的第二个因子。丢了 = 信封全废
├── keys/<thumbprint>.json     0600  信封,一把一个(v1 或绑了硬件的 v2)
├── dids/<did>.json            0644  已发布的文档(含自签 proof),给外面看
├── audit/YYYY-MM.jsonl        0600  审计日志。按月分片,链 + 锚
├── audit/.lock                0600  串行化追加的那把跨进程锁
├── log/serve.log              0600  守护进程的日志,给人排查用
└── run/
    ├── keyd.sock                    守护进程的 Unix socket
    └── keyd.pid               0600  它的 pid(`stop` 读这个)
```

**权限:** 目录 `0700`,秘密文件 `0600`,公开文件 `0644`。

写入一律先写临时文件再 `rename`(`write_atomic`),这样断电不会留下半个文件。

## 文件名是拍平过的

`keys/` 和 `dids/` 底下的文件名都是外部输入,所以两层都要挡路径穿越:

- `<did>` —— DID 里的 `:` 换成 `_`,其余不在白名单的字符同样换成 `_`。所以 `did:wba:example.com:agents:bot:e1_abc…` 落在 `dids/did_wba_example.com_agents_bot_e1_abc….json`
- `<thumbprint>` —— 走单独的一条校验

## `device.secret` 值得单说一句

**文件整个不见了**和**它是新生成的**,是两件事,而且**分开报**:

- 文件缺失时报 `BadDeviceSecret`
- 而"生成一个新的"是另一条路 —— 新生成的那把打不开旧信封(报 `BadPassphrase`,和口令错一模一样)

**系统不会"顺手帮你恢复"。** 放在一起人才能看出自己丢了什么。

## `log/` 和 `audit/` 是两件事,别混

| | `audit/` | `log/` |
|---|---|---|
| 是什么 | 哈希链加锚,是对外的**证据** | 给人看的运行记录 |
| 能删吗 | 不能 —— 删了就断链 | 随时可以删 |

把它们塞进一个文件,前者就失去了意义。

## 审计日志

`audit/YYYY-MM.jsonl` 按月分片。每一行是一条事件,和前一行**链**起来 —— 少了一行、改了一行,链就对不上。每个分片另外有一个**锚**,抓住整个文件被截断这种情况:链管不了"尾巴没了"。

### 链是跨月延续的

换月不重置,所以本月文件第一行的 `prev` 指的是上个月最后一行。

于是"总共有多少条"用的是记录自己带的 `seq`(累计),不是这个文件里数出来的行数;`seq` 每一行必须正好比前一行大 1,不是就是被删过或改过号。

### 打开日志要走的是一整条链

链跨月延续,那么"本月对不对"就取决于前面每一份月份文件。只验本月那份的话,一个**已经过去的**月份连它的末行一起被改掉就没人看得见 —— 而这个月的记录会照样接着那条被改过的尾巴。

所以 `AuditLog::open` 从**最早**那份月份文件走起,那份的第一行必须接在 `GENESIS` 上。它不是的话,要么更早的月份被删了,要么整条链是重写出来的。

::: info 代价是常数级的读盘,而它躲不掉
要发现旧月份被改过,就得把旧月份读一遍。这不是可以靠往锚里多存一个摘要省掉的东西 —— 链就在文件里,存一份整链摘要只是把同一件事说两遍。
:::

### 一次追加是一段临界区

**写它的不止守护进程一个。** 守护进程攥着一份到进程结束,而每一条 CLI 命令各自开一份 —— 它们完全跑得起来的时间正是守护进程正忙的时候。

两个写者各记各的去写,后写那行的 `prev` 就指向一条不是它前驱的记录,链断。而链断是这个文件**唯一**用来指认事故的信号:让一次合法的并发造出这个信号,比日志乱一点糟得多 —— 真的出了事和"有两个进程在写"会变成同一句话,而人看见几次之后只会学会忽略它。

所以"读尾哈希 → 写记录 → 写锚"整段走一把 `audit/.lock` 上的 `flock`。

锁是那个 `.lock` 而不是某一份 `.jsonl`:后者换月会换成另一个文件,锁它挡不住换月那一瞬间。

锁**只包住一次追加**,不包住 `AuditLog` 的一生 —— 攥着不放等于"守护进程在跑的时候所有命令卡死",而那正是一次正常的并发操作。

锁里第一件事是**跟磁盘对账**:文件的字节数和自己记得的不一样,就说明别人写过,把状态重读一遍;**文件变短则拒绝写着走** —— 那是锚存在的意义,悄悄接着写就把一次截断掩盖成了"看起来一直是这样"。

### 日志里没有秘密

没有口令、没有种子、没有私钥字节。它记的是"谁在什么时候让哪把钥匙签了什么",以及 `IMPORT` / `EXPORT` 这类会改变状态的事。

**"会改变状态的事"包括本机自己那些。** 一条身份在这台机器上出现有两条路:`IMPORT`(别人那份搬进来)和 `KEYGEN`(这里自己生一把)—— 只记前者,事后拿一个 DID 问"它什么时候出现的"就漏掉最常走的那条。

同理,`PUBLISHED` 记的是文档落进本机 `dids/` 那一份,而 `publish --out DIR` **不记**:那条路本机一个字节都没变,记下来会让人以为本地那份文档是它。

`PUBLISHED` 和 `DOCUMENT_READ` 用的是同一个摘要函数,所以**拿一个摘要在整份日志里搜一遍,得到的就是这份文档的一生**:谁什么时候写下去的、谁什么时候取走的、什么时候被改的。

## 目录复制与恢复

完整软件目录包含 device.secret，加上正确口令可以解封。只复制信封、缺少 device.secret 或所需硬件根时拒绝。Linux v2 离线迁移保留加密信封、device.secret、文档与审计；恢复副本始终保留在管理员保护路径。
