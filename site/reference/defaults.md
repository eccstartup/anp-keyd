# 不显然的默认值

这一页是这份文档里**最该在上线前读一遍**的。每一条背后都有一个"为什么不那样",而其中几条如果理解反了,后果不是报错,是**不报错地出事**。

## 关于坐标和文档

### `keygen --spec` 没有默认值

DID 是"坐标 + 公钥"算出来的,而坐标必须是**你写在文件里的**那几个 —— 由工具替你挑一个,等于替你决定身份挂在哪儿。

### 规格文件拒收未知字段

"我以为我声明了"和"它真的声明了"是两件事,而一个拼错的键正是这两件事开始分岔的地方。悄悄忽略它,等于让这两件事永远分不了岔。

### `spec --host` 拒收 IP 字面量

did:wba 要求 FQDN。这一条在读规格文件时就报,不等到人坐下来敲口令。

### 根密钥的 fragment 写不进规格文件

它不是一条声明,是本工具自己认根密钥用的名字;开放出去能造出一份**本工具自己看不懂的文档**。

### `publish` 不给 `--spec` 就沿用本地那份文档的声明

重发一次文档不该顺手把 service 条目清掉 —— 那是**不报错的丢东西**。

### `publish --spec` 的坐标必须和 `--did` 说的一致

对不上直接拒,而不是挑一个信:拿一个 DID 去签另一个地方的文档,是这里**最贵的一种错**。

## 关于守护进程

### `serve --idle 0` 是"立刻上锁",不是"永不"

想要永不,别用 0。

### `serve` 默认进后台,`stop` 靠 pid 文件找到它

pid 文件会被**核对**:里面那个号码现在跑的**不是这个二进制**,就拒绝动手 —— pid 会被回收,而 `stop` 发的是 SIGTERM。

对不上时它**不杀、也不删那个文件**。

### `serve --system` 不给 `--allow-binary` 就拒绝启动

一个守护进程服务多个 uid 时,**uid 已经不是承诺的粒度了** —— 只配了 uid 的"多用户"是假的多用户,那就不过。

::: tip 不知道值该填什么?
先拿一个匹配不上的 pin 起一次,守护进程会把每一条被拒的连接连同**可以直接抄进命令行**的那个 pin 写进 `log/serve.log`。
:::

## 关于"能签任意字节"的那两条路

这两条默认都**关着**,而且都是 `serve` 上的开关。

### `sign --raw` 默认关

那是守护进程里**唯一一条**能给调用方任意签名的路。要用得先 `serve --allow-raw-signing`。

### `sign --challenge` 也是一个开关,默认同样关

而且它签的东西和 `--raw` 是**一回事**:同一把钥匙、同样签你给的原字节。

**唯一的区别是它的输入有上界** —— 文件最多 256 字节,超出在协议层就被拒,**连钥匙都不碰**。

::: info 那道墙是它存在的全部理由
有上界,它就长不成"帮我把这份文档签了"。

它给注册这类流程用(服务端发一个随机串,你签它的原字节),用不着就不开。
:::

### 两条的关系不是"各管各的"

**`--allow-raw-signing` 是更宽的那扇门,开了它,挑战签名那条路也一起开了。**

反过来不成立:`--allow-challenge-signing` 不会打开 raw。

## 关于 nonce

### `--nonce` 不给,上游会自己随机一个

守护进程把"没有"交给上游,而**上游的默认行为是随机生成一个** —— 签名里照样有一行 `nonce=`,签名照样验得过,只是那个值**跟你的请求体没有关系**。

这不是"某个开关忘了关",是两条路各自成立:

| 你要做的事 | 该怎么做 |
|---|---|
| 单次请求,只要防重放 | 不用给,随机 nonce 就是干这个的 |
| 服务端要求 nonce 和**请求体里那个**是同一个值 | 必须自己给 —— 只有调用方知道那个值是多少 |

给了之后守护进程只做两条校验:**不超过 256 字节**,且**不含 `"`**。它管的是"能不能写进签名基",不管含义。

## 关于 URL

### `sign --url` 里的 URL 会按 URL 解析器的写法规范化

host 归一成小写,默认端口去掉 —— `https://example.com:443/x` 按 `https://example.com/x` 签。

验签方是**自己解析 URL 再算一遍** `@authority` 的,两边必须是同一串。照字面签 `:443` 会得到一个"签名无效",**把人指向钥匙而不是指向 URL** —— 这是这条默认值存在的理由。

path、query、fragment 一个字节不动,非默认端口照旧。

## 关于迁移和硬件

### `migrate --allow-different-subject` 默认关

默认放行等于让一次打错字的 `--to` 变成一次**无人察觉的冒名**。

### `--hardware` 默认 `none`

硬件根是**要的人开口要**的东西。

**要了而没有,是错误,不是降级** —— 见[硬件根](/advanced/hardware-root)。

## 还有一对不对称

**导入默认有,导出默认没有。**

恢复自己的身份不该需要一次特殊编译;而**交出**身份应该。
